Baloo: MPPI & RL Theoretical Formulations, Cost Duality & Tuning Guide

Reference & Synthesis Guide: Comprehensive theoretical documentation for the Baloo dual-arm soft robot manipuland-lifting task. This document details exact variable definitions, mathematical cost-reward duality, a rigorous comparison between Reinforcement Learning (RL) and Model Predictive Path Integral (MPPI) control, the theoretical departures between Baloo's MPPI and Classical MPPI, and the complete hand-tuning parameter catalog.

2. Mathematical Formulations & Cost-Reward Duality

2.1 The Duality Principle: Minimization vs. Maximization

Reinforcement Learning and Optimal Control are dual formulations of sequential decision-making under uncertainty. Their mathematical formulations reflect opposite sign conventions:

Reinforcement Learning (Reward Maximization)

RL seeks a parameterized policy \(\pi_\theta(a|s)\) maximizing expected cumulative discounted return:

$$J_{\text{RL}}(\pi) = \mathbb{E}_{\tau \sim \pi} \left[ \sum_{t=0}^{T} \gamma^t R_t(s_t, a_t) \right]$$

where \(R_t > 0\) rewards desirable behavior, and penalties are negative.

Optimal Control / MPPI (Cost Minimization)

MPPI solves a receding-horizon trajectory optimization problem minimizing expected cumulative cost:

$$J_{\text{MPPI}} = \mathbb{E}_{\tau} \left[ S(\tau) \right] = \mathbb{E}_{\tau} \left[ \sum_{t=0}^{H-1} q(s_t, a_t) + \phi(s_H) \right]$$

where \(q(s_t, a_t)\) is running cost and \(\phi(s_H)\) is terminal cost.

The exact bridge connecting the two domains is:

$$\text{Cost } S(\tau) \equiv - \text{Return } \mathcal{R}(\tau)$$
Why \(r_{\text{task}}\) Enters with a Negative Sign in MPPI:
In mpc_controller.py (line 109), the total rollout cost is computed as: $$S_k = \sum_{t=0}^{H-1} c_{\text{guide}}(a^{(k)}_t, a_{\text{nom}, t}) - r_{\text{task}}(s^{(k)}_H)$$ Because \(r_{\text{task}}\) is defined as a positive reward (higher elevation \(\Delta z\) and successful lift bonus \(+10\) increase \(r_{\text{task}}\)), subtracting it (\(- r_{\text{task}}\)) ensures that a high task reward drives the total cost \(S_k\) to a more negative (desirable) value, which maximizes its importance weight in the softmax selection.
Why \(c_{\text{guide}}\) is Formulated with a Negative Sign:
In mpc_controller.py (line 75), the guidance cost is: $$c_{\text{guide}}(a, a_{\text{nom}}) = -W_{\text{guide}} \cdot \exp\left(-\frac{1}{2} \|a - a_{\text{nom}}\|^2\right)$$ When an action perfectly tracks the nominal baseline (\(a = a_{\text{nom}}\)), the squared norm \(\|a - a_{\text{nom}}\|^2 = 0\), yielding \(\exp(0) = 1\) and a minimal cost of \(-W_{\text{guide}}\). As the action deviates from nominal, \(\exp \to 0\), raising the cost to \(0\). Thus, staying close to the nominal trajectory minimizes running cost.

2.2 Detailed Mathematical Equations

Reinforcement Learning Reward Formulation (Curtis's lucky-silence-739)

The reward at step \(t\) combines task achievement with a decaying imitation prior:

$$R_t = r_{\text{task}}(s_t) + r_{\text{guide}}(a_t)$$
  1. Task Reward Component: $$r_{\text{task}}(s_t) = \begin{cases} +10.0, & \text{if } z_{\text{box}, t} \ge z_{\text{init}} + 0.5\,\text{m} \quad (\text{success bonus}) \\ -2.0, & \text{if } \arccos(\hat{\mathbf{z}}_{\text{box}} \cdot \hat{\mathbf{z}}_{\text{world}}) > 80^\circ \quad (\text{tip penalty}) \\ 0.0, & \text{otherwise} \end{cases}$$
  2. Decaying Action Guidance Prior: $$r_{\text{guide}}(a_t) = w_{\text{imit}}(t) \cdot \exp\left(-\frac{1}{2} \|a_t - a_{\text{nominal}, t}\|^2\right)$$ $$\text{where } w_{\text{imit}}(t) = 0.1 \cdot \max(0, 1 - \alpha \cdot t), \quad \alpha = 10^{-7}$$

Baloo MPPI Controller Formulation

For each candidate trajectory \(k \in \{1, \dots, K\}\), the candidate action sequence over the lookahead horizon \(H\) is sampled as:

$$a_t^{(k)} = a_{\text{nom}, t} + \epsilon_t^{(k)}, \qquad \epsilon_t^{(k)} \sim \mathcal{N}(0, \sigma^2 I), \quad t \in \{0, \dots, H-1\}$$

The cumulative trajectory cost \(S_k\) evaluated at the end of the MuJoCo simulation rollout is:

$$S_k = \underbrace{\sum_{t=0}^{H-1} -W_{\text{guide}} \exp\left(-\frac{1}{2} \|\mathrm{clip}(a_t^{(k)}, -1, 1) - a_{\text{nom}, t}\|^2\right)}_{\text{Running Guidance Cost } \sum q(a_t)} - \underbrace{\left[ W_{\text{height}}(z_{\text{box}, H}^{(k)} - z_{\text{init}}) + \mathbb{I}(\text{tip}) R_{\text{tip}} + \mathbb{I}(\text{lift}) R_{\text{lift}} \right]}_{\text{Terminal Task Reward } r_{\text{task}}(s_H^{(k)})}$$

Importance Sampling & Action Synthesis:

$$w_k = \frac{\exp\left(-\frac{S_k - \min_j S_j}{\lambda}\right)}{\sum_{i=1}^K \exp\left(-\frac{S_i - \min_j S_j}{\lambda}\right)}, \qquad a_0^* = \sum_{k=1}^K w_k \, a_0^{(k)}$$

Only the first control vector \(a_0^*\) is applied to the real/simulated plant. At the subsequent timestep \(t+1\), the horizon slides forward by one step, and the entire optimization repeats (Receding Horizon Principle).

3. In-Depth Comparison: RL vs. MPPI Cost Functions

3.1 Architectural Similarities

  • Shared Task Objective: Both controllers evaluate physical success according to identical physical criteria: secure bilateral contact, vertical elevation \(\Delta z \ge 0.5\,\text{m}\), and maintaining box tilt below \(80^\circ\).
  • Open-Loop Motion Prior Inductive Bias: Both formulations employ an exponential squared-distance action guidance kernel (\(\exp(-\frac{1}{2}\|a - a_{\text{nom}}\|^2)\)) anchored to the same OpenLoopHuggerPolicy state machine to avoid exploration failure in high-dimensional continuous space.

3.2 Fundamental Differences

Dimension RL (Curtis's PPO Model) Baloo MPPI Controller Why It MUST Be Different (Physical / Algorithmic Necessity)
Continuous Height Shaping None (\(W_{\text{height}} = 0\)). Purely sparse reward (+10 only upon full 0.5m lift). Heavy Continuous Slope (\(W_{\text{height}} = 157.45\)). Rewards millimeter-level upward motion. Horizon & Credit Assignment: RL trains offline over millions of interactions using Generalized Advantage Estimation (GAE) and temporal difference learning. A learned critic network \(V(s)\) bootstraps and backpropagates the distal \(+10\) terminal reward backward across hundreds of timesteps. Giving dense height reward to RL often causes severe reward hacking (e.g., repeatedly vibrating the box or dropping it after a slight lift).

In contrast, MPPI has no learned critic and evaluates only a short receding horizon (\(H=16\) steps = \(0.8\,\text{s}\)). A heavy box cannot be raised \(0.5\,\text{m}\) within 0.8 seconds. If MPPI had no continuous height slope, \(\mathbb{I}(\text{lifted})\) would be identically \(0\) across all \(K\) rollouts during the critical lift phase. The cost landscape would be completely flat (\(\nabla S = 0\)), causing softmax weights to become uniform (\(w_k = 1/K\)), rendering MPPI completely blind to lift dynamics! Thus, MPPI must have a dense height slope to provide local gradients within its short window.
Imitation Weight Dynamics Decays to Zero: \(w_{\text{imit}}(t) = 0.1 \cdot \max(0, 1 - \alpha t) \to 0\). Static & Persistent: \(W_{\text{guide}} = 0.185\) throughout all steps and rollouts. Memory vs. Online Sampling: RL updates its neural network weights permanently. Once policy gradient updates discover stable grasping, the policy retains the grasp autonomously, allowing the imitation scaffold to be safely removed so the network can surpass the open-loop baseline.

MPPI has no memory; it solves an optimization problem from scratch at every step. If \(W_{\text{guide}}\) were decayed to zero, random Gaussian exploration across 25 coupled tendon actuators in contact-rich physics would suffer from the curse of dimensionality, immediately causing the arms to flail, lose contact, and drop the box. The guidance weight must remain active as a permanent structural prior.
Temporal Horizon & Evaluation Global / Infinite Horizon: Discount factor \(\gamma = 0.99\), episode length up to 2,000 steps. Local / Receding Horizon: Finite window \(H = 16\) steps (\(0.8\,\text{s}\)), un-discounted (\(\gamma = 1.0\)). Computational Tractability: Simulating \(K=31\) rollouts of length 2,000 in real time would require millions of MuJoCo physics steps per control cycle (completely impossible for online control). MPPI must truncate the horizon to \(H=16\) to maintain a 20 Hz control loop.
Action Selection Mechanism Parametric neural forward pass \(\pi_\theta(s_t)\) in \(< 1\,\text{ms}\) (offline learned). Online Monte Carlo path integral expectation over forward simulated physics rollouts (online compute). RL front-loads computation into hours of offline GPU cluster training. MPPI requires zero pre-training but demands high real-time multi-core CPU throughput during execution.

4. Baloo's MPPI vs. Traditional / Classical MPPI

4.1 Foundations of Classical MPPI (Williams et al., 2015, 2017)

Classical Model Predictive Path Integral control was mathematically derived from stochastic optimal control theory for continuous-time dynamical systems described by control-affine Stochastic Differential Equations (SDEs):

$$dx_t = f(x_t)\,dt + G(x_t)\big(u_t\,dt + d\omega_t\big), \qquad d\omega_t \sim \mathcal{N}(0, \Sigma_\omega\,dt)$$

In the seminal work by Williams et al. ("Model Predictive Path Integral Control: Theory and Applications to Autonomous Driving"), the objective is to minimize the expected path cost:

$$S(\tau) = \phi(x_T) + \int_0^T \left( q(x_t) + \frac{1}{2} u_t^T R u_t \right) dt$$
The Fundamental Theorem of Traditional MPPI:
To transform the nonlinear Hamilton-Jacobi-Bellman (HJB) partial differential equation into a linear PDE solvable via the Feynman-Kac path integral, the control cost matrix \(R\) must satisfy an exact relationship with the control noise covariance \(\Sigma\) and temperature \(\lambda\): $$R = \lambda \, \Sigma^{-1}$$ This strict condition enables the quadratic control effort term \(\frac{1}{2} u_t^T R u_t\) to cancel with the drift terms emerging from Girsanov's theorem change of measure between the uncontrolled passive dynamics and the controlled trajectory distribution.

4.2 Key Departures in Baloo's MPPI Formulation

Baloo's MPPI diverges from textbook MPPI in four fundamental ways:

  1. Expert Action Prior Centering vs. Control-Shift Warm-Start:
    • Traditional MPPI: Perturbations are sampled around the previous iteration's shifted control sequence \(\mathbf{u}^{(i)} = [u_1, u_2, \dots, u_{H-1}, u_{\text{init}}]\), or around zero control (\(u = 0\)) if cold-started.
    • Baloo MPPI: Perturbations are strictly centered around a time-indexed expert motion primitive \(a_{\text{nom}, t}\) precomputed by OpenLoopHuggerPolicy.
  2. Guidance Similarity Kernel vs. Quadratic Effort Penalty:
    • Traditional MPPI: Imposes a quadratic control penalty \(\frac{1}{2} u_t^T R u_t\), explicitly penalizing actuator effort and seeking minimum-energy solutions.
    • Baloo MPPI: Discards the quadratic effort penalty entirely and replaces it with the non-linear Gaussian guidance cost \(c_{\text{guide}}(a_t, a_{\text{nom}, t}) = -W_{\text{guide}} \exp(-\frac{1}{2} \|a_t - a_{\text{nom}, t}\|^2)\).
  3. Decoupled Hyperparameters vs. Strict Theoretical Coupling:
    • Traditional MPPI: Enforces \(R = \lambda \Sigma^{-1}\). Changing the temperature \(\lambda\) or noise \(\Sigma\) automatically alters the control effort penalty.
    • Baloo MPPI: Decouples \(\lambda\), \(\Sigma\), and \(W_{\text{guide}}\) into independently tuneable hyper-parameters optimized for physical grasping performance.
  4. Contact-Rich Complementarity vs. Smooth Affine Drift:
    • Traditional MPPI: Assumes smooth, Lipschitz-continuous drift dynamics \(f(x)\) and well-defined control authority \(G(x)\).
    • Baloo MPPI: Operates directly within MuJoCo's discontinuous linear complementarity problem (LCP) contact physics, non-linear Coulomb friction cones, and soft continuum tendon constraints.

4.3 Do These Differences Matter? Better or Worse?

Where Baloo's Formulation is VASTLY BETTER

  • Taming the Curse of Dimensionality: In a 25-DoF soft continuum robot with 12 pneumatic pressure chambers and an elevator, unguided traditional MPPI (sampling around zero control or unconstrained shifted inputs) suffers total exploration collapse. With \(K=31\) samples, the odds of 25 random actuators stumbling upon a synchronized, bilateral hugging and lifting grasp are effectively zero. Centering exploration around \(a_{\text{nom}, t}\) guarantees that all \(K\) rollouts remain within the basin of attraction of viable physical grasps.
  • Preventing Tendon Slack & Pneumatic Instability: Traditional quadratic effort \(\frac{1}{2} u^T R u\) penalizes high actuator commands, driving tendon pressures toward zero. In pneumatic continuum arms, dropping pressure to zero causes limp limbs, loss of tension, cable derailment, and catastrophic drops. Baloo's \(c_{\text{guide}}\) maintains the required pre-tensioning established by the nominal gait.
  • Practical Robustness over Broken Theory: Contact discontinuities violate the foundational SDE assumptions of traditional MPPI anyway. Enforcing \(R = \lambda \Sigma^{-1}\) would handicap tuning without restoring mathematical rigor. Treating MPPI as an adaptive importance-weighted Monte Carlo optimizer is practically superior for contact mechanics.

Trade-offs & Limitations (Where It Is Worse / Constrained)

  • Locally Biased to the Nominal Primitive: Because exploration is confined to a Gaussian neighborhood around \(a_{\text{nom}, t}\), Baloo's MPPI cannot discover fundamentally novel grasping strategies (e.g., scooping from underneath, tipping the box horizontally, or using a single-arm pull) that lie outside the nominal manifold.
  • Loss of Information-Theoretic Optimality: Without \(R = \lambda \Sigma^{-1}\), the mathematical guarantee that MPPI minimizes the Kullback-Leibler (KL) divergence to the optimal path distribution no longer formally holds. It functions as an empirical cross-entropy / CMA-ES variant with importance weighting.
  • Sensitivity to Baseline Timing: If the nominal trajectory has poor timing (e.g., attempting to lift before contact is established), the controller can struggle if \(W_{\text{guide}}\) is set too high.

6. Step-by-Step Tuning & Validation Workflow

Follow this standard engineering protocol when adjusting parameters or evaluating baseline performance:

  1. Edit Parameters: Modify hyperparameter values in baloo_mujoco_sim/controllers/mpc/mpc_controller.py (lines 19–30) or in evaluate_unified.py (lines 392–402).
  2. Visual Sanity Check: Run an interactive GUI episode on box index 0 (default box or LHS sample) to observe arm behavior, contact formation, and elevator coordination: 
    python -m baloo_mujoco_sim.controllers.mpc.mpc_controller 0
  3. Fast Headless Subset (50 LHS Perturbation Boxes): Run an un-rendered 50-trial benchmark across Latin Hypercube Sampling (LHS) variations to verify stability and success rate: 
    python evaluate_unified.py --controller mppi --percentile p99 --condition nopert --num_trials 50
  4. Full 1,000-Trial Comprehensive Benchmark: Execute the unified benchmark script across all 1,000 randomized boxes and conditions: 
    bash run_weekend_eval.sh
